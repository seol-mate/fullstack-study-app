Claude(너)와 Codex CLI가 번갈아 주장·반박하며 결론을 도출한다. 코드는 수정하지 않고, 결과는 토론 기록 파일로만 남긴다.

## 사전 확인
- `codex login status`가 "Logged in"이 아니면 토론하지 말고 "codex login 필요"라고 보고한 뒤 종료한다.

## 절차 (최대 3라운드)
1. 주제와 쟁점을 정리하고, 관련 파일을 읽어 너의 초기 입장을 작성한다.
2. Codex에게 보낼 프롬프트를 임시 파일(스크래치 디렉터리)에 쓴다. Codex는 파일을 직접 읽을 수 없으므로(Windows의 read-only 샌드박스가 명령 실행을 차단한다) **토론에 필요한 코드·문서 내용을 프롬프트에 직접 붙여 넣는다**. 파일마다 경로를 제목으로 달고 필요한 부분만 발췌한다. 프롬프트 본문에는 다음을 담는다: 주제, 너의 입장, 첨부한 코드, "파일을 읽거나 명령을 실행하려 하지 말고 제공된 내용만으로 답하라. 동의하지 않는 점과 근거를 구체적으로 반박하고, 합의되는 부분은 명시하라."
   ```
   codex exec -s read-only --ephemeral -C <프로젝트 루트> -o <응답파일> - < <프롬프트파일>
   ```
   프롬프트는 `-`와 stdin 리다이렉트로 전달한다(인자로 주고 stdin을 열어두면 입력 대기로 멈춘다). 응답은 `-o` 파일에서 읽는다.
3. Codex의 반박을 검토한다. 타당하면 수용하고 입장을 수정, 아니면 근거를 들어 재반박하고 다음 라운드로 보낸다.
4. 양쪽이 합의했거나 3라운드가 끝나면 종료한다.

## 규칙
- Codex 호출은 항상 `-s read-only`. 쓰기 권한·`--dangerously-*` 옵션은 쓰지 않는다.
- `.env*`, 비밀번호, 토큰 등 비밀 값은 프롬프트에 넣지 않는다. 첨부할 파일은 네가 직접 고르고, `.env*`는 절대 첨부하지 않는다.
- 동의를 위한 동의를 하지 않는다. 근거가 부족하면 입장을 유지한다.
- 모델이 낸 사실 주장(API, 버전, 동작)은 코드나 문서로 확인한 것만 결론에 넣는다.

## 산출물
`docs/debates/<날짜>-<주제 슬러그>.md`에 저장하고 요약만 보고한다.
- 주제, 라운드별 요약(Claude / Codex)
- 합의된 결론
- 미합의 쟁점과 각 측 근거 (최종 판단은 사용자 몫)
